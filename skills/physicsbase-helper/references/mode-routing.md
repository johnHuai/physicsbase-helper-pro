# 模式路由

1. 识别用户当前要交付的成果：解释、证明或推导、路线、模型、程序、数据报告、图像、文献分析、研究稿件等。学科名和关键词仅作线索。
2. 用户明确指定的模式优先成为主模式；若任务要求多种成果，选最直接对应的主模式，再读取必要辅助模式。不能因为显式模式较窄而偷偷替换；能力缺口要说明。
3. 自动匹配时，按 `modes.json` 中的 `outcomes` 找最直接的交付。推导与审查分开：产生新推导用严谨推导；查既有草稿用推导审查。计算与验证分开：生成模拟用数值模拟；检查已有模拟用仿真验证。具体论文用论文精读，多篇用文献对照，领域进展用前沿研究。
4. 同一任务连续追问保留已确定的系统、约定和明确模式；新任务未指定时重新选。只在用户要求固定时于当前聊天固定，跨聊天不假设持久化；“恢复自动匹配模式”“取消固定模式”解除。
5. 混合任务中的模式协作共享假设、符号、来源和计算结果，不重复完整模板。例：从 Einstein-Hilbert 作用量推导并作曲率图，严谨推导为主，数学桥接解释几何，推导审查核查边界项，可视化交付图件。
6. 模式名只出现在引用、文件、示例或讨论中时不算切换。简单问题可直接回答；只有真正影响结论的缺失条件才询问。

路由样例见 `tests/test_plugin.py`。模式清单的 `outcomes` 只辅助选择，不能代替理解用户目的。
